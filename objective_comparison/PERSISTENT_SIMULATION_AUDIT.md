# Persistent simulation audit

The reference experiment starts in `run.py`, which loads the Phase 3 manifest, Phase 2 marketplace records and SUMO mobility. `ScenarioInputs.problems` assembles one `EpochProblem` per active second. Request, PUE and cell identifiers are stable across snapshots. Array indices are local to each snapshot. Each request supplies demand in Mbps, arrival, priority and a price ceiling. The provider table supplies current access/backhaul capacity and prices. Coverage determines the serving cell, and the cell supplies its remaining capacity after background load.

`run.prepare` uses `LSTMDistanceSurvivalModel`, the original checkpoint and fitted scaler, and `build_reliability_table` to compute scores from online windows. Scores are checked against recorded Phase 3 inference. Phase 3's candidate flags incorporate range, availability, history, radio and resource eligibility. The runner also applies the validated 0.62 threshold to fresh scores. `sinr.snapshot` recalculates path loss, noise and co-channel interference from current positions using the configured PC5 and gNodeB profiles. The ratio is linear when passed to the Shannon calculation.

## Implementation boundary

The original allocator assumes uniform physical bandwidth limits. An initial solve with active reservations needs individual residual RHS budgets in MHz per PUE and cell. The separate adapter uses the same allocation expressions with the reserved Mbps and MHz moved to the right side of the original inequalities. The original bandwidth profiles, objectives, allocator parameters and stateless code remain intact.

A connection record keeps stable request, provider and cell identifiers, the original delivered split and both bandwidth allocations. Retained sessions are checked before new allocations. If current capacities make existing reservations incompatible, longest-established connections get first consideration, with request ID breaking ties. Original assigned bandwidth, including spare capacity awarded by a policy, stays reserved while the connection is valid. A cell change invalidates a reservation on that old cell. A PUE-only assignment depends only on the PUE path. The shared physical audit checks the original capped achievable rate. Exact still limits newly scheduled PUE bandwidth to the link's saturation point during optimization; a reserved width can sit above a new saturation point when SINR improves, with the same evaluator clipping achievable rate to the cap.

Phase 5 has a separate lifecycle and a useful precedent for stable session IDs and residual reservation accounting. Its concrete coordinator is bound to Phase 4 allocators, Mbps-only assignments, Phase 4 pricing, optional proactive switching and a drop timer. Reusing that coordinator would introduce those semantics, so Experiment B uses a small shared lifecycle over the Experiment A allocation arrays.

All four algorithms preserve full demand for each CUE they serve. Heuristics can serve a subset by skipping whole requests, while an infeasible Exact pending batch returns no new allocation. Valid retained Exact service continues. The original evaluator sets the full-epoch objective bill to undefined for incomplete service, but separately returns the actual supplied-traffic payment and its components. The persistent report will use that payment for full-population monetary totals and retain objective cost and comparable common-feasible comparisons separately. The original runner's CSVs and the original report and figures remain separate.

## Updated protocol: initial allocation and immediate gNodeB fallback

The revised brief supersedes the earlier pending/reallocation design from the earlier brief. All four algorithms are called only on the first active second of a request. A retained PUE assignment is checked against the current eligible link, original delivered split and reserved bandwidth, current gNodeB cell where used, and the original feasibility evaluator. Loss of validity permanently moves the request to gNodeB-only service. An initial gNodeB assignment also remains gNodeB-only. An initially unserved request remains unserved for that window.

The original runner combines its snapshot preparation and allocation dispatch. The original allocator uses a scalar bandwidth per transmitter, and its gNodeB-only branch is embedded in its constructive loop. To preserve the stateless source byte for byte, Experiment B isolates the snapshot adapter and residual-budget policy code in separate modules. It reuses the inference, SINR and shared evaluator, and tests the adapted policies against the original with identical inputs and no reservations. Residual budgets move fixed previously reserved usage to the right side of the original inequalities. The physical limits and mathematical formulas stay the same.

When a PUE fails, the shared fallback uses the original constructive gNodeB-only feasibility condition: full demand must fit residual cell Mbps and radio capacity, coverage must exist, and the gNodeB bill must fit the request budget. A fallback episode with insufficient resources records an outage. The request remains gNodeB-only and the same feasibility check can restore service in a later second. Existing gNodeB commitments get priority over new fallback claims; fallbacks are processed before new requests. Simultaneous claims use establishment time and request ID as deterministic ordering. The common fallback uses the original minimum necessary bandwidth for delivered demand, followed by the original spare-bandwidth assignment within the fallback batch. The fixed η fee applies each second with positive PUE service, and ceases in the same second the PUE connection fails.

The initial opt-in edits were withdrawn when the revised brief explicitly protected Experiment A source. Experiment B instead contains a narrow copy of the policy bodies with only the RHS inputs adapted and a separate snapshot adapter. The original entry points and all result files retain their original bytes.
